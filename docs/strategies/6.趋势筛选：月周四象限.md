# 趋势筛选 · 月/周 MACD 四象限（regime · 设计稿）

> 状态：**设计中（未实现）**  
> 建议 API：`strategy=regime`（或 `trendFilter`）  
> 展示名：**趋势筛选** / **周期象限筛选**  
> 定位：在**梯子策略**之上增加「宏观周期自动路由 + 多档梯子联检」

---

## 1. 产品定义

**一句话**：先用**月 K、周 K 的 MACD 符号**判定标的所处宏观周期（四象限之一），再按该周期规定的档位，对 min30 / 日 / 周 / 月梯子做 **AND 联检**；各档梯子参数可独立自定义。

```
命中 = 可识别宏观周期（象限命中且该象限已启用）
     ∧ 成交额等硬过滤
     ∧ 该周期要求的每一档梯子均独立命中
```

与现有能力的关系：

| 能力 | 区别 |
|------|------|
| **梯子策略（ladder）** | 用户手选 短/中/长 **单档**；MACD 为各档可选附加项 |
| **无阻力梯子（nrf）** | 固定日/周/月「无阻力 MACD 门」+ 用户手选梯子组合 |
| **本方案（regime）** | **月/周 MACD 自动分象限**，象限决定联检哪些梯子；MACD 只负责分周期，不参与各档梯子内部过滤 |
| **周期共振（resonance）** | 旧突破引擎 + 双 MACD>0；非梯子内上移 |
| **深跌反弹（rebound）** | 大周期 MACD<0 + 小周期>0 + 旧突破；象限与联检规则均不同 |

---

## 2. 宏观周期：月 × 周 MACD 四象限

### 2.1 判定口径

- **数据**：当前最新一根**月 K**、**周 K** 的 MACD 柱（与 `UnilateralMacdTools.isMacdPositive/Negative` 一致）。
- **符号**：
  - `> 0`：MACD 柱严格大于 0
  - `< 0`：MACD 柱严格小于 0
  - `= 0`：见 §2.3

### 2.2 四象限与梯子联检（初版规则）

| 象限 | 月 MACD | 周 MACD | 周期名称 | 需满足的梯子（全部 AND） |
|:----:|:-------:|:-------:|----------|--------------------------|
| **Q1** | > 0 | > 0 | **超级周期** | 仅 **min30 梯子**（ultra） |
| **Q2** | > 0 | < 0 | **反弹周期** | **周K梯子**（medium）+ **日K梯子**（trend）+ **min30梯子**（ultra） |
| **Q3** | < 0 | > 0 | **震荡周期** | **周K梯子**（medium）+ **日K梯子**（trend）+ **min30梯子**（ultra） |
| **Q4** | < 0 | < 0 | **熊市/混沌**（待定） | 见 §5 |

说明：

- Q2 与 Q3 的**梯子组合相同**，差异仅在宏观语境（月强周弱 vs 月弱周强），列表与消息中须带**周期 Tag** 区分。
- Q1 隐含假设：大周期已走好，只需 min30 做**入场时机**；若需更严，可在参数中可选叠加月K梯子（见 §4.2）。
- 联检时 **必须关闭** trend/medium/long 内置的 `requireUltra`，min30 单独作为一档检查，避免重复计超短（与 nrf 相同原则）。

### 2.3 MACD = 0 的边界

建议默认策略（实现时可做成参数）：

| 选项 | 行为 |
|------|------|
| **A（推荐）** | 既不视为 >0 也不视为 <0 → **该象限不命中**，不入池 |
| B | 归入相邻象限（需明确定义，易引入抖动，不推荐） |
| C | 单列「中性」第五类，默认不扫描 |

### 2.4 判定流程

```text
取月K MACD、周K MACD
        │
        ├─ 月 > 0 ─┬─ 周 > 0 → Q1 超级周期 → [min30]
        │          └─ 周 < 0 → Q2 反弹周期 → [周 + 日 + min30]
        │
        └─ 月 < 0 ─┬─ 周 > 0 → Q3 震荡周期 → [周 + 日 + min30]
                   └─ 周 < 0 → Q4 待定
        （月或周 MACD = 0 → 默认不命中）
```

## 3. 梯子引擎映射

| 用户说法 | 策略引擎 | K 线 / 分组桶 | 参数前缀 |
|----------|----------|---------------|----------|
| min30 梯子 | `ultra` | 30m / 交易日 | `ul*` |
| 日K 梯子 | `trend` | 日K / 自然周 | `tr*` |
| 周K 梯子 | `medium` | 周K / 自然月 | `md*` |
| 月K 梯子 | `long` | 月K / 自然年 | `lg*` |

突破逻辑复用 v2「梯子内上移」现有 `*BreakoutTools`，**不**复用 resonance/rebound 的 `PreGoldenBreakoutTools`。

各象限联检示例：

```text
Q1：hit = ultraPass
Q2：hit = mediumPass ∧ trendPass ∧ ultraPass
Q3：hit = mediumPass ∧ trendPass ∧ ultraPass
```

## 4. 参数模型

### 4.1 策略级参数

| 字段（建议） | 说明 | 默认 |
|--------------|------|------|
| `rgMinAmountWan` | 最低日均成交额（万） | 5000 |
| `rgEnableSuper` | 启用 Q1 超级周期 | true |
| `rgEnableRebound` | 启用 Q2 反弹周期 | true |
| `rgEnableOscillation` | 启用 Q3 震荡周期 | true |
| `rgEnableBear` | 启用 Q4（规则定稿后） | false |
| `rgNeutralPolicy` | MACD=0 处理：`skip` / … | `skip` |

### 4.2 四档梯子 Profile（可自定义，各象限共用）

每档（min30 / 日 / 周 / 月）独立一套参数；**象限规则只决定启用哪几档**，不重复定义突破逻辑。

| 参数 | 含义 | 对应现有字段 |
|------|------|--------------|
| 基准背景数 | 前 N 日/周/月/年 | `prevDays` / `trPrevWeeks` / `mdPrevMonths` / `lgPrevYears` |
| **当前K突破** vs **本周期内突破** | 突破K是否必须为最新一根 | `*RequireCurrentBreakout` |
| 最低成交额 | 可继承策略级或分档覆盖 | `*MinAmountWan` |
| 宏观底部强突破 | 分位 < 30% 时须 close > ref.high | 已实现，建议默认开 |
| 档内 MACD 过滤 | 趋势筛选下**默认全关**（MACD 已用于象限） | `*Require*Macd` |

**Q1 可选增强**：`rgSuperRequireMonthLadder` — 为 true 时 Q1 由「仅 min30」变为「月K + min30」。

### 4.3 存储与 UI 建议

- 前端「梯子策略」增加模式：**单档**（现有）| **趋势筛选**（本方案）。
- 四档 Profile 与单档模式**共用同一套参数存储**，切换模式只改「用哪几档、如何组合」，避免两套配置。
- 趋势筛选模式下隐藏 短/中/长 手选条，列表展示 **周期 Tag** + 各档 ✓。

## 5. 待拍板：第四象限（Q4）

月 < 0 且 周 < 0 时，初版建议 **默认不入选**（`rgEnableBear=false`）。若后续要做，常见两种方向：

| 方案 | 联检 | 适用场景 |
|------|------|----------|
| **Q4-A（更严）** | 月K + 周K + 日K + min30 四档全 AND | 熊市里只做极弱反弹、多重确认 |
| **Q4-B（更松）** | 仅月K梯子 | 等大周期趋势反转左侧观察 |
| **Q4-C（关闭）** | 不扫描 | 默认，减少噪音 |

定稿前不在生产环境默认启用 Q4。

## 6. 技术架构（建议）

### 6.1 为何必须后端 composite

若前端分别请求 `strategy=trend|medium|ultra` 再求交集：

- 无法保证同一扫描时刻、同一 regime 语义；
- 分页 `totalNum` 与客户端交集失真；
- `rescan` 无法写入单一策略池。

因此应在后端一次 eval 完成，建议新增 **`RegimeStrategy`（或 `TrendFilterStrategy`）**：

```text
RegimeStrategy
  → RegimeClassifier.classify(stock)      // 月/周 MACD → Q1~Q4
  → RegimeRule.requiredTiers(quadrant)    // 该象限需要的梯子列表
  → for tier in required:
        LadderEvaluator.run(stock, tier, params.getProfile(tier))
  → hit = all passed
  → RegimeMessageBuilder.fill(checkResult)
```

`LadderEvaluator` 直接调用现有 `UltraShortBreakoutTools`、`TrendBreakoutTools`、`MediumBreakoutTools`、`LongBreakoutTools` 及对应 FilterTools（关闭档内 MACD / requireUltra）。

### 6.2 API（草案）

| 接口 | 说明 |
|------|------|
| `GET /stock/findMy?strategy=regime&...` | 预览 |
| `POST /stock/strategy/rescan?strategy=regime&...` | 写库 |

查询参数：`rg*` + 四档 `ul*` / `tr*` / `md*` / `lg*`（按当前象限实际用到的档位传递）。

### 6.3 输出消息（草案）

```text
趋势：[REGIME:SUPER] 超级周期|月MACD>0·周MACD>0
信号：30m✓

趋势：[REGIME:REBOUND] 反弹周期|月MACD>0·周MACD<0
信号：周✓·日✓·30m✓

趋势：[REGIME:OSC] 震荡周期|月MACD<0·周MACD>0
信号：周✓·日✓·30m✓
```

列表 Tag 示例：`超级周期` / `反弹周期` / `震荡周期`。

## 7. 与「无阻力梯子（nrf）」的对比

| 维度 | nrf（已实现） | regime（本方案） |
|------|---------------|------------------|
| MACD 门 | 日+周+月 **无阻力门**（>0 或 破前高） | 仅 **月+周** 定象限 |
| 梯子组合 | 用户 **手选** 四种之一 | **象限自动** 决定联检档位 |
| 日 MACD | 参与固定三门 | 不参与象限（仅在 Q2/Q3 的日梯子里体现结构） |
| 适用 | 已验证的固定 MACD 过滤 + 灵活梯子 | 宏观自适应、减少手选档位 |

两者可并存：`nrf` 偏「规则固定、参数灵活」；`regime` 偏「宏观分周期、自动多档」。
